# Обновления Companion через GitHub

Репозиторий: https://github.com/yashkarpsher/companion

## Первый релиз

1. Открой https://github.com/yashkarpsher/companion/releases/new.
2. Создай тег `v0.13.1`, назови релиз `Companion 0.13.1`.
3. Прикрепи **Majestic-Companion-0.13.1.zip** из этой поставки. Можно добавить файл `.zip.sha256` рядом.
4. Опубликуй обычный релиз, без отметок Draft и Pre-release. Для проверки без авторизации репозиторий должен быть публичным.

Для перехода с версии 0.12.0 и более ранних один раз установи 0.13.1 вручную и перенеси папку `data`. После этого будущие версии можно ставить из настроек программы.

## Следующие версии

Измени номер в CompanionAssembly.cs, обнови CompanionReadme.txt и выполни:

```powershell
.\package-update.ps1
```

Скрипт собирает приложение и отдельный установщик обновления, создаёт чистый ZIP без пользовательских данных и контрольную сумму. Он не публикует релиз автоматически.

Создай стабильный GitHub Release с тегом `vНОМЕР`, например `v0.13.2`, и прикрепи `Majestic-Companion-0.13.2.zip`. Имя ZIP и тег должны совпадать с версией внутри EXE. Автоматические GitHub-архивы Source code для обновления не подходят.

В корне ZIP обязательны: `Majestic Companion.exe`, `Companion Updater.exe`, `Microsoft.Web.WebView2.Core.dll`, `Microsoft.Web.WebView2.Wpf.dll`, `WebView2Loader.dll`. Файл инструкции и SHA256SUMS.txt необязательны. Папку `data` в архив не включать.

## Как работает установка

Программа обращается к GitHub Releases при запуске (это можно выключить) или по кнопке в настройках. Новая версия предлагается пользователю; без подтверждения установка не начинается. ZIP проверяется по SHA-256, полученной от GitHub, и по номеру версии EXE. Обновляется только фиксированный список файлов приложения.

После подтверждения перезапуска Companion сохраняет профиль, закрывает окна и запускает отдельный установщик. Установщик ждёт завершения программы, делает резервную копию заменяемых файлов в `update-backup-…`, заменяет файлы и запускает Companion. Папка `data` не заменяется. При обычной ошибке копирования установщик возвращает старые файлы. Это не защищает от отключения питания посреди записи; сохранённая резервная копия остаётся в папке программы.

Папка установки должна быть доступна пользователю для записи. Установщик не запрашивает права администратора. Проверка хеша подтверждает целостность архива, но не заменяет доверие к владельцу репозитория: защити GitHub-аккаунт и доступ к публикации релизов.

Официальное описание Releases API и полей assets/digest: https://docs.github.com/en/rest/releases/releases

При старте новая версия предлагается вопросом «Да / Нет». Согласие сразу запускает загрузку и установку с перезапуском; второго подтверждения нет. При отсутствии сети стартовая проверка проходит без сообщений. Ручная кнопка в настройках остаётся.
